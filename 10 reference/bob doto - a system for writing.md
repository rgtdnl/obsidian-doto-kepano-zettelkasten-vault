**why i picked this up:** the user's own zettelkasten practice; a beginner's guide from a practitioner rather than a theorist.

## captures
one idea per line, with a locator (page, timestamp).

- (p. 11) the method in five steps: capture → transform → connect → track → write.
- (p. 11) the zettelkasten is organized bottom-up; structure emerges from relationships, not predetermined categories.
- (p. 19) process the inbox at least once a week.
- (p. 22) fleeting notes with tasks are not ideas; they never become main notes.
- (p. 27) not writing ideas down because you think you'll remember them is not a dependable system.
- (p. 28) a reference note is one long note per source with brief citations and locators.
- (p. 31) Luhmann's reference notes: page numbers + a few words that would later jog his memory; bibliographic info on the back.
- (p. 45) not all captures are gold; you don't need to understand an idea's relevance to cite it.
- (p. 47) minimum main note = single idea + link to another note.
- (p. 50) titles should be declarative statements, not descriptors: "Not all apples are edible", not "Apples and edibility".
- (p. 51-52) creating main notes: retype the idea in full sentences, consider relations, link with context, add ID, title.
- (p. 61-62) Luhmann called his zettelkasten a "septic tank"; notes don't need to be perfect or current thinking.
- (p. 72-73) link dumping: dropping uncontextualized links assumes future-you remembers; state why each "see" link was made.
- (p. 74-75) atomicity: split complex ideas; watch for "but" and "however".
- (p. 85-89) folgezettel: first note 1.1, branches 1.1a, 1.1a1; new ideas get the next number; unrelated ideas start a new section. IDs are street addresses, not a tree. Never renumber.
- (p. 88) section headings can be added later as labels only, never as categories for filing.
- (p. 96-97) hub notes: entry points listing where trains of thought start.
- (p. 97-99) structure notes: places to unpack and organize related ideas semantically; can become rough drafts.
- (p. 100-101) keyword index: austere, a keyword and a few note IDs, built for serendipity (Luhmann: at most four references per keyword in 60,000 notes).
- (p. 104-105) clusters: long alphanumeric IDs show developed trains of thought, clues to what to write about.
- (p. 115-116) don't let the zettelkasten write for you; the box is a terrible writer.
- (p. 140-144) daily journal + creative logs: "For others"/"For me" purpose prompts; record what was done, what needs attention, what's next.
- (p. 145-150) task-focused project management: define project, brainstorm tasks, do dates, gather resources, do only today's tasks, record progress.
- (p. 155-156) not a second brain; don't import old notes; one to ten minutes per main note; OK to take breaks.

## verbatim
> "Every note is an element which receives its quality only from the network of links and back-links within the system." — Luhmann (p. 60)

> "Link dumping is the act of dropping uncontextualized links into your notes, assuming you'll remember why the connections were made in the future." (p. 72)

> "The slip box provides combinatorial possibilities which were never planned, never preconceived." — Luhmann (p. 79)
